## 2. 잘 된 점

**업무가 실제로 흘러간다.** 할 일을 지우는 대신 처리한다. 공지는 확인 기록이 남고, 이슈는 작업 시작 → 해결(메모 필수)로 트래커 상태가 실제로 바뀌고, 메일은 AI 초안을 사람이 승인해야 발송되며 발송하면 할 일이 "회신 발송"이라는 결과와 함께 "처리한 일"로 이동한다. 열린 할 일이 3 → 0으로 줄어드는 것까지 확인했다.

**동료가 답한다.** 직접 쓴 메일에는 메일 답장이, 채팅에는 직무에 맞는 답이 **최대 3개 안(실측 1~2개)**으로 온다. LLM을 쓰더라도 누가 답할지와 개수 제한은 코드가 정하고, 모델이 지어낸 숫자는 걸러낸다.

**권한이 서버에서 강제된다.** 다른 사람의 메일 열람, 임원 채널 접근·작성, 남의 이슈 변경, 재무 데이터 조회가 모두 403으로 막힌다. 로그인 없이는 401. 외부 수신자 메일은 확인 없이 보내면 409. 수신자 11명 초과·빈 본문·1,001자 채팅은 422. 인젝션 문구가 든 안내 질문에도 링크나 알 수 없는 동작은 나오지 않았고, 분당 20회 제한도 작동했다.

**숫자가 일을 만든다.** 계약 갱신 임박, 예산 지출 페이스 초과, 매출 계획 미달, 런웨이 부족이 해당 담당자의 아침 브리핑에 **할 일**로 실제로 올라온다(CFO 4건 확인). 재무 화면은 권한 없는 계정에는 숫자 대신 안내만 보인다.

**세계관이 서로 맞물린다.** 인원 추이는 로스터 입사일에서 계산하고, 고객 계약일은 제품 출시일보다 앞서지 않으며, 위키의 한도는 AI 안전장치의 한도와 같다. 현금이 음수가 되는 분기는 없다. 이런 정합성은 테스트로 지킨다.

**성능과 안정성.** 주요 API 중앙값 2~8ms, 콜드 브리핑 82ms. 신규 clone으로도 그대로 실행된다.

## 3. 발견한 문제와 조치

### 이번 점검에서 발견해 고친 것

| # | 문제 | 영향 | 조치 |
|---|---|---|---|
| 1 | **출근 웹훅 재전송 가능.** 서명은 검증했지만 시각을 검사하지 않아, 한 번 서명된 요청을 가로채면 나중에 다시 보낼 수 있었다 | 낮음~중간 (남의 출근을 임의 날짜에 기록) | 본문에 `ts`를 넣어 서명하고 5분 넘은 요청은 401, `ts` 없으면 400. 테스트 추가 |
| 2 | **평가 정답표가 새 기능을 모름.** 갱신·예산 알림이 정답표에 없어 브리핑 정밀도가 0.80으로 떨어져 보였다 (고치는 과정에서 일시적으로 0.51까지 내려간 오류도 직접 만들었다가 바로잡음) | 평가 신뢰도 | 라벨이 있는 사용자에 한해 알림을 정답에 포함. 정밀도 **0.93** |

### 이번 대화 중에 사용자 보고로 발견해 고친 것 (참고)

| 문제 | 원인 | 조치 |
|---|---|---|
| 이슈 "작업 시작"에서 403 | 임원에게 에스컬레이션 이슈를 보여 주면서 상태 변경은 담당자만 허용 | 임원은 에스컬레이션 이슈에 한해 허용, 아니면 이유를 문장으로 안내 |
| 관리자 콘솔이 전부 비어 있음 | 새 DB라 0과 빈 목록 | 운영 이력 시드(문서 약 150, LLM 호출 185, 초안 30 등) |
| **자동 단계가 유지되지 못함** | 최근 20건이 전부 맞아도 신뢰구간 하한이 0.84라 기준 0.90 미달로 즉시 강등 (데이터가 비어 있어 드러나지 않던 결함) | 최근 일치율 자체로 판정. 테스트 추가 |
| 단계 버튼이 눌리지 않음 | 버튼처럼 보이는 표시판이었고, 승격 실패는 조용히 무시 | 실제 버튼화, 근거 없는 승격은 확인 창, 성공·실패 안내 |

### 남아 있는 문제 (미해결)

| 우선순위 | 문제 | 설명 |
|---|---|---|
| ~~높음~~ **해결** | ~~웹훅 기본 비밀값이 코드에 있다~~ | 기본값 제거. 한 프로세스 서버는 켤 때마다 무작위 키 생성, 값이 없거나 16자 미만이면 503으로 거부 (README 참고) |
| ~~중간~~ **해결** | ~~피드백 → 개선 고리가 안 닫힌다~~ | "관련 없음"은 이제 그 사람에게만 같은 종류를 숨기고(서명 기준), 필수 공지·숫자 알림·내 P1/P2는 숨길 수 없다고 이유와 함께 거절한다. 여러 명이 숨긴 종류는 관리자 콘솔에 규칙 검토 후보로 올라온다. 재생 평가 0.75 → 1.0 |
| 중간 | **동료 답변이 가끔 맥락 밖 말을 한다** | 실제 모델(Gemini 경량)에서 "처리했어요"에 "PR 올려주시면 리뷰할게요"처럼 답한 사례 1건. 표본 20개·1~3회 실행이라 우열 판단 불가 |
| 중간 | **Gemini 무료 티어가 한도(429)에 자주 걸린다** | 마지막 확인 때 20건 중 16건이 429. 평가는 이제 API 오류를 점수에서 제외하고 따로 센다. 서비스에서는 규칙 답장으로 대체되지만 지연이 보인다. 안정 측정에는 유료 한도나 다른 모델이 필요 |
| 낮음 | 브리핑이 아직 없을 때 **404**를 돌려줘 브라우저 콘솔에 빨간 줄이 남는다 | 기능에는 영향 없음. 200 + 빈 값으로 바꾸는 게 깔끔하다 |
| 낮음 | 승격 승인·단계 변경은 DB에 저장되지만 데모 DB는 앱을 다시 켜면 시드로 돌아간다 | 의도된 동작이나 사용자가 놀랄 수 있다 |
| 낮음 | 같은 날 갱신이 몰려 알림이 한꺼번에 뜬다 (D-69 여러 건) | 데이터가 정적이라 생기는 현상 |

- **보안 전수 점검**: 위 22개 탐침은 대표 사례일 뿐 침투 테스트가 아니다
