# Project Nowhere (프로젝트 노웨어)

[회고(Step별)](RETROSPECTIVE.md) · [세계관 기준 문서](world/WORLD.md) · [실측 결과](eval/RESULTS.md) · [에이전트 규칙](AGENTS.md)
> 가상 기업 **노웨어**를 위한 LLM 업무 자동화 플랫폼: 출근 브리핑 비서 · 문서 자동 처리 · 단계적 자동화 · 평가/운영 체계

구성: `app/`(비서·문서 처리 서비스) · `world/`(노웨어 사내 시스템: SSO·메일·메신저·이슈·포털·근태) · `eval/`(평가) · `tests/`

## 공식 사이트 (`site/`)
가상 기업 노웨어의 소개·제품·채용 페이지(정적 HTML, 빌드 없음). 모든 페이지 상단에 가상 기업 고지가 있고, 제품 화면은 실제 앱에서 캡처했습니다.
글꼴은 Pretendard(SIL OFL 1.1)를 `site/fonts/`에 자체 호스팅합니다(동적 서브셋이라 페이지에 필요한 글자 조각만 내려받음, 라이선스 파일 동봉). 메타 설명·Open Graph·파비콘·`sitemap.xml`·`robots.txt`가 들어 있고, 주소는 기본 Pages 주소(`jobless-fish.github.io/Project-Nowhere`)를 가정했습니다.
로컬 확인: `python -m http.server -d site 8080`. GitHub Pages 배포: 저장소 Settings → Pages → Source를 **GitHub Actions**로 선택하면 `site/` 변경 시 자동 배포됩니다.

## 한 줄로 실제 서버 실행 (권장)
```bash
cd web && npm install && npx vite build && cd .. && pip install -r requirements.txt
uvicorn server:combined --port 8000        # http://localhost:8000  — 앱·비서 API(/api)·사내 시스템(/world)이 한 주소에서 동작
```
Docker: `docker compose up --build` (Dockerfile은 위 과정을 그대로 자동화. 이 환경에는 Docker가 없어 **이미지 빌드는 직접 검증하지 못했습니다**). Render 배포용 `render.yaml`도 있으나 마찬가지로 미검증입니다.
`tests/test_e2e_server.py`가 실제 서버를 띄워 HTTP만으로 출근 웹훅 → 브리핑 → 초안 승인 → 수신자 도착 → 권한 → 피드백 수집까지 검증합니다.

## 실행 (개발용: 서버 분리 + 화면 개발 서버)
```bash
pip install -r requirements.txt && (cd web && npm install)
DEFAULT_MODE=shadow ./run_demo.sh          # 사내 시스템(:9000) + 비서(:8000)
cd web && npm run dev                      # http://localhost:5173  (직원 앱 + 관리자 콘솔)
```
`web/`은 React + TypeScript(Vite) 앱입니다. 디자인 토큰(`src/styles.css`)과 공용 컴포넌트(`src/ui.tsx`)로 라이트/다크, 모바일 하단 내비를 지원합니다.
출근하기 → 근태 시스템 → 서명된 웹훅 → 비서 브리핑 생성 흐름이 화면에서 그대로 동작합니다.

## 문서 자동 처리 (DocFlow 모듈)

메일·문서 텍스트를 받아 **LLM이 분류·추출**하고, **업무 규칙(가드레일)** 을 통과하면 **ERP/HR/구매/CS 시스템에 API로 자동 연계**합니다.
애매하거나 위험한 건은 **사람 검수 큐**로 보내고, 모든 처리는 **감사 로그**와 **비용·지연 메트릭**으로 남습니다.

> 핵심 메시지: 자동화(연계)는 기본이고, **LLM 결과의 품질·안전·비용을 운영 관점에서 책임지는 구조**.

## 흐름
```
문서 → LLM 추출(JSON, 스키마 검증, 1회 재시도) → 가드레일(신뢰도/금액/필수값)
     ├─ 통과 → ERP 연계(processed)
     └─ 보류 → 사람 검수(승인/수정/반려) → ERP 연계(approved)
모든 단계: audit 로그 · llm_calls(토큰/지연/비용) 기록
```

## 유령 안내자 "노워"
화면 위를 하늘하늘 날아다니며 "여기를 보세요"라고 짚어 주고, 질문에 답하는 비서 챗봇입니다(앱 오른쪽 아래, 숨기기·다시 부르기 가능).
- **할 수 있는 것은 말하기와 짚기뿐입니다.** 메일 발송, 승인, 설정 변경은 하지 못하고 그렇게 말합니다. 짚을 수 있는 곳과 이동할 화면은 서버가 **실제로 존재하는 것만** 허용합니다(모델이 지어내거나 메일 속 지시에 속아도 엉뚱한 곳을 가리키지 못함). 답변의 링크는 제거하고, 분당 20회로 제한합니다.
- LLM이 없거나 실패하면 규칙 기반으로 답합니다. 3D 렌더링이 불가능한 환경에서는 평면 유령으로 대체됩니다.
- 움직임: 모델에 뼈대가 없어서 정점 셰이더로 옷자락 물결·끌림·몸 흔들림을 만들고, 곡선 경로로 날며 도착하면 가만히 멈춥니다(말풍선 버튼을 누르기 쉽도록). 움직임 줄이기 설정을 존중합니다.
- 검증: `tests/test_guide.py`(서버), `web/e2e/ghost-flight.cjs`·`ghost-a11y.cjs`(실제 브라우저: 곡선 경로, 강조 테두리 위치, 키보드, 모바일).

### 크레딧
3D 모델: **"Ghost Game Ready"** by [BarnusModels](https://sketchfab.com/barnusmodels), [CC BY 4.0](http://creativecommons.org/licenses/by/4.0/) — [원본](https://sketchfab.com/3d-models/ghost-game-ready-b553ea4141f34a14b654736a317610b8). 이 프로젝트에서는 `web/public/ghost/`에 두고 셰이더로 흔들림을 입혔습니다(원본 파일은 수정하지 않음). 대화창 하단에도 같은 표기가 있습니다.

## 가상 기업 "노웨어(Nowhere)"
임직원 217명, 본부·실 9개, 팀 32개, 근무지 3곳의 조직과 사내 디렉터리(조직도·인물 검색·보고 라인)를 갖췄습니다. 메일 2,505건·채팅 1,200건·이슈 180건의 업무 트래픽과 정답 라벨, 피싱·어려운 사례까지 생성하며, 대규모 평가 결과는 [`eval/RESULTS.md`](eval/RESULTS.md)에 있습니다(Gemini 정밀도 1.0, 재현율 0.93~0.96, 규칙 기반 대비 어려운 사례에서 크게 우세, 단 표본 20명·편차 큼). 자세한 설정과 앞으로 채울 항목은 [`world/WORLD.md`](world/WORLD.md)에 있습니다. — 핀테크·인슈어테크 스타트업
실제 회사처럼 **자체 시스템들이 따로 있는 환경**(`world/`)을 만들고, AI 비서가 그 시스템에 API로 연동되게 했습니다.
| 시스템 | 내용 |
|---|---|
| SSO | 사내 계정·토큰 발급(데모용 HMAC 토큰. 실제는 OIDC/SAML) |
| 사내 메일 서버 | 받은편지함(페이지네이션), 메일 조회, 발송. 당사자가 아니면 403 |
| 사내 메신저 | 공개/비공개 채널. 비멤버는 목록에도, 메시지 조회에도 접근 불가 |
| 이슈 트래커 | 담당자·팀·임원 에스컬레이션 기준 가시성 |
| 포털 | 공지·게시판(대상 부서 제한) |
| 근태 | 출근 시 비서에 **HMAC 서명 웹훅** 전송 |
- 권한은 **각 시스템이 사용자 본인 토큰으로 강제**합니다. 비서는 사용자가 직접 열 수 있는 것 이상을 볼 수 없습니다.
- 임직원 13명, 임원 전용 채널, 인젝션 메일, 광고, 규제 관련 메일 등 실무형 함정을 시드 데이터에 심어 두었습니다.
```bash
./run_demo.sh                 # world(:9000) + assistant(:8000) 두 프로세스
python -m eval.briefing_eval --world
```

## AI 업무 비서 (출근 브리핑 · 사내 소식 요약)  → `/assistant-ui`
출근 도장을 찍으면 밤새 도착한 메일·이슈를 정리해 **오늘의 할일**을 보고하고, 별도 탭에서 Slack·공지·게시물을 요약합니다. 사원과 임원은 같은 구조에서 **역할별로 다른 브리핑**(사원=실행할 일, 임원=결정·승인·리스크)을 받습니다.
| 안전장치 | 구현 |
|---|---|
| 출처 강제(환각 차단) | 모든 할일은 실제 원본 `source_ids`를 인용해야 함. 없는 출처를 인용한 항목은 코드에서 제거 |
| 권한 필터 | 사용자·역할·팀 기준으로 원본 단계에서 걸러냄(임원 전용 채널은 사원에게 아예 전달 안 됨) |
| 프롬프트 인젝션 | 메일·채팅 본문은 신뢰하지 않는 데이터. 지시문 의심 항목은 할일에서 제외하고 "보안 확인 필요"로 격리 |
| 장애 대응 | LLM 실패 시 규칙 기반 요약으로 자동 대체(`degraded` 표시) |
| 재출근 | 같은 날 다시 찍어도 브리핑을 재생성하지 않음(비용·할일 목록 일관성) |
| 피드백 | 완료/관련 없음 기록 → 이후 평가셋·프롬프트 개선에 사용 |
평가: `python -m eval.briefing_eval` (필수 처리 항목 재현율·정밀도, 인젝션 유출 0건).
**데모는 샘플 데이터**(`app/assistant/demo_data.json`)입니다. 실제 연동은 `Source` 인터페이스(메일·Slack·Jira·그룹웨어)를 구현하고, 출근 이벤트는 근태 시스템 웹훅이 `POST /assistant/clock-in`을 호출하도록 연결합니다. 사용자 식별은 SSO로 교체해야 합니다.

## 실측 결과
실제 모델(Gemini 경량 모델, 무료 티어)로 돌린 첫 결과는 [`eval/RESULTS.md`](eval/RESULTS.md)에 있습니다. 문서 분류 필드 정확도 0.966~0.974, 브리핑 재현율 0.83 / 정밀도 1.00 / 인젝션 유출 0건. 표본이 작고 1회 실행이라 프롬프트 v1/v2의 우열은 가려지지 않았으며, 한계와 함께 기록했습니다.

## 사용자 피드백 → 평가셋 → 회귀 게이트 (피드백 루프)
```
사용자: 할일 완료 / "관련 없음" · 초안 그대로 발송 / 수정 / 반려
   └─ harvest ─> 평가 사례(입력 스냅샷 + 사람의 판단)   [관리자 콘솔 "학습 데이터" 또는 POST /assistant/eval/harvest]
        └─ python -m eval.feedback_eval ─> 현재 프롬프트·규칙·모델로 재생 → 기준선(eval/baseline.json)과 비교 → 하락 시 CI 실패
```
- 할일 사례: "관련 없음"은 인용되면 안 되고, 완료한 할일은 인용되어야 함. 초안 사례: 새 초안이 사람이 최종 발송한 글과 얼마나 가까운가.
- 수집 시 인젝션 의심 메일은 사례에서 제외하고, 중복 수집은 무시합니다(멱등).
- `eval/make_feedback_cases.py`가 데모 사용 기록으로 `eval/feedback_cases.jsonl`을 재현 생성합니다. 변경 후 점수를 받아들이려면 `--update-baseline`.
- **현재 알려진 약점**: 사용자가 "관련 없음"으로 표시한 보안교육 공지를 비서가 아직 할일로 올립니다(할일 통과율 0.75). 기준선에 그대로 기록했고, 이보다 나빠지면 CI가 막습니다.
- 한계: mock 기반이라 초안 유사도(0.511)는 모델 품질이 아니라 기준선 장치의 동작 예시입니다. 실제 수집에는 직원 동의·개인정보 마스킹·보관기간 정책이 필요합니다.

## 비서가 행동하기 — 회신 초안 (사람 승인 후 발송)
브리핑의 메일 할일에서 **답장 초안**을 만들고, 사용자가 수정·승인해야만 **본인 계정으로** 발송됩니다.
| 안전장치 | 구현 |
|---|---|
| 승인 없이는 발송 없음 | 초안은 `proposed` 상태로만 존재. 승인 시에만 메일 서버 `/mail/send` 호출 |
| 본인 명의 | 사용자 본인 토큰으로 발송(비서 전용 계정 없음). 수신자 메일함에서도 발신자는 사용자 |
| 중복 발송 방지 | 결정은 원자적 선점(`UPDATE ... WHERE status='proposed'`)으로 1회만 통과 |
| 외부 수신자 | 별도 확인 체크 없이는 승인 거절. 금액·계좌·송금 표현이 있는 외부 초안은 아예 차단 |
| 의심 메일 | 인젝션으로 격리된 메일, 메일이 아닌 할일(이슈 등)에는 초안을 만들지 않음 |
| 실패 기록 | 발송 실패는 `failed`와 사유로 남고 사라지지 않음 |
| 품질 지표 | 초안 그대로 발송 / 수정 후 발송 / 반려 / 차단 비율을 관리자 콘솔에서 확인 → 자동화 후보 판단 근거 |

### 초안 신뢰 → 미리 작성 (같은 단계 사다리, 회신 전용 기준)
사용자가 초안을 **고치지 않고 그대로 보낸 비율**이 사람과의 일치율입니다(수정·반려는 불일치). 20건 이상이고 신뢰구간 하한이 0.80을 넘으면 관리자 콘솔이 승격을 *추천*하고, 담당자가 승인하면 **출근 시 사내 수신자 초안을 미리 만들어 둡니다.**
- 승격해도 **자동 발송은 없습니다.** 발송은 언제나 사람이 누르는 승인 뒤에만 일어납니다(테스트로 확인: 승격 후에도 발송된 메일 0건).
- **외부 수신자는 승격 대상이 아닙니다**(모드 변경 API도 404). 인젝션으로 격리된 메일, 메일이 아닌 할일에는 미리 작성하지 않습니다.
- 최근 결과의 하한이 0.60 아래로 떨어지면 자동으로 "제안" 단계로 되돌립니다.
- 위험이 낮은 승격(초안만 준비)이라 업무 문서 승격(30건, 0.95)보다 기준을 낮췄습니다. 기준은 `app/config.py`에서 조정합니다.

## 점진적 자동화 (Shadow → Assisted → Auto)
문서 유형별로 AI에게 자율권을 단계적으로 부여합니다. 승격은 **사람과의 일치율**로만 결정합니다.
| 단계 | 동작 | 다음 단계 조건(기본값) |
|---|---|---|
| shadow | AI는 제안만 기록, 사람이 평소대로 처리 후 결과를 입력해 비교 | 표본 20건 이상 & 일치율 **95% 신뢰구간 하한** ≥ 0.85 |
| assisted | AI가 채운 값을 사람이 모두 승인/수정 | 표본 30건 이상 & 하한 ≥ 0.95 |
| auto | 가드레일 통과 건 자동 연계 + 10% 감사 샘플 사람 확인 | 최근 결과 하한 < 0.90 이면 **자동 강등** |
- Wilson 하한을 써서 "5건 중 5건 일치" 같은 작은 표본이 완벽해 보이는 착시를 막습니다.
- 승격은 추천만 하고 담당자가 승인, 강등은 즉시 자동 적용합니다.
- 기본값은 안전하게 shadow입니다(`DEFAULT_MODE`).

## LLMOps 요소
| 요소 | 구현 |
|---|---|

| 안전장치 | 신뢰도 임계값, 금액 한도, 프롬프트 인젝션 방어는 **코드 규칙**으로(모델에 의존 안 함) |
| 사람 개입 | `POST /documents/{id}/review` (승인/수정/반려, 담당자 기록) |

## 실행
```bash
pip install -r requirements.txt
LLM_PROVIDER=mock uvicorn app.main:app      # API 키 없이 데모 (규칙 기반 모의 LLM)
export ANTHROPIC_API_KEY=...                # 설정하면 자동으로 Claude 사용
uvicorn app.main:app                        # http://localhost:8000  (UI) / /docs (API)
docker compose up --build
python -m pytest -q
python -m eval.run_eval                     # 평가
```
주요 환경변수: `LLM_PROVIDER(auto|claude|mock)`, `CLAUDE_MODEL`, `CONFIDENCE_THRESHOLD`, `PRICE_IN_PER_MTOK/PRICE_OUT_PER_MTOK`, `ERP_URL`(미설정 시 내장 모의 ERP), `DOCFLOW_API_KEY`.
